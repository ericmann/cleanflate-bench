# cleanflate-bench build plan
Derived from docs/SPEC.md v(unversioned, commit 082220a) on 2026-09-30. SPEC.md wins over this file.

## Decisions
- Phases → SPEC §7 milestones B0–B10 map 1:1 to Phase 0–Phase 10, in SPEC order (T1-critical B0–B5 first). Nothing is merged or reordered, except the conformance runner, which moves to Phase 5 (see Spec issues 3).
- Orchestration language → Python 3.12 managed by `uv` (package `cfbench/`, run as `uv run --frozen python -m cfbench.<module>`), with Rust only for the timed harness and subject shims. Analysis, charts and kit rendering are easiest to keep deterministic in Python. Bash 3.2 on macOS rules out non-trivial shell scripts.
- Timing harness → a custom Rust harness (`crates/harness`), not criterion. Criterion cannot shuffle cells across subjects that live in separate binaries (needed by §3.2). The custom harness keeps criterion's rigor: warm-up, at least `perf.min_samples` samples, each sample sized to at least `perf.min_sample_ms`, and every raw sample stored. Python computes the median and a seeded bootstrap 95% CI from those samples.
- One binary per subject (`cfb-cf`, `cfb-zlib`, `cfb-zlib-nohw`, `cfb-zng`, `cfb-zrs`, `cfb-mox`, `cfb-zsys`) → `zlib`, the hardware-CRC-disabled `zlib-nohw` and `zsys` all export the same C symbols and cannot share a process. The orchestrator runs one process per cell, in seeded random order.
- Pinned versions → zlib 1.3.2 (release tarball), zlib-ng 2.3.3 with the native `zng_` API (tag tarball), zlib-rs via `libz-rs-sys =0.6.8` (wraps `zlib-rs` 0.6.8; default features `std,rust-allocator`), `miniz_oxide =0.9.1` (default features, so no `simd`), Rust toolchain 1.89.0 (the same toolchain cleanflate pins), infgen at commit `1e36c3da205ce3da7df1abd1f1c765a3cf49b267`, JPlag 6.3.0 jar. These were the latest releases on 2026-09-30. Each tarball's SHA-256 is recorded in `config/subjects.toml` the first time it is downloaded.
- Rounds (`config/rounds.json`) → round 1 = `v0.1.0-cleanroom` = `e94efcfa92de1f2d301d3a0208f67dcc303a9ba9`, round 2 = `v0.2.0-cleanroom` = `d3e911b463c8aed50c3fcc7c17e0a26e8af1d298`, round 3 = `v0.3.0-cleanroom` = `85f210084a367dcc706c732f5776bf0563cdc0cd`. "Round" means a cleanflate release round (one Foundry flight per tag). It never means a Foundry review round, which §3.9 reports separately as "review rounds per milestone". The three tags match SPEC §3.5's description (initial build / first perf pass / v0.3.0).
- cleanflate consumption → Cargo git dependency `ssh://git@github.com/ericmann/cleanflate.git` pinned by `rev` (the repo is private, so `.cargo/config.toml` sets `net.git-fetch-with-cli = true`). Data and source come from a read-only full clone at `third_party/cleanflate` (gitignored), detached at the round-3 SHA. The URL can be overridden with `CFB_CLEANFLATE_URL`, for example a local path. The only writes into the clone are cleanflate's own gitignored products: its corpora fetch and its oracle corpus generator, run with `--locked`. A pristine check (`git status --porcelain` empty, HEAD equal to the pinned SHA) runs after every such step.
- One-shot mode → fresh decoder state per operation, the whole input in a single decode call, and a caller-preallocated output buffer of exactly the decompressed length. At most one extra zero-length call is allowed when an API needs it to report end-of-stream. Streaming small = 1 KiB in / 4 KiB out, streaming large = 1 MiB in / 1 MiB out (config keys). Every subject verifies checksums with its default options.
- miniz_oxide has no gzip framing → mox gzip cells are recorded as `unsupported` and never measured. A hand-rolled gzip wrapper would measure the harness, not mox.
- Workloads → generated by `cfb-zlib compress` (stock zlib 1.3.2, memLevel 8, default strategy). The gzip header is set with `deflateSetHeader` to os=255, mtime=0, so workload bytes are identical on M-A and M-B. Their hashes are committed in `data/manifests/workloads.json`. Tiny (≤1 KiB) workloads are the 64/256/1024-byte prefixes of `canterbury/alice29.txt`, `canterbury/kennedy.xls` and `silesia/xml`.
- Who measures what → the implementer runs on the Linux x86_64 workstation (M-B). It commits full raw data only for deterministic, non-timing categories: env, pins, size, unsafe, deps, similarity, effort, content features, malformed matrix and conformance. Timing-sensitive full runs (perf, perf-native, framing, checksums, trajectory, fuzz budget, bomb sweep) and everything on M-A are human-run on a quiet machine. They are listed under each phase's manual check. The implementer only runs their quick profile, which writes to gitignored `data/smoke/`.
- Make targets → `make <category>` measures (writes raw) and then derives (`results/*.csv`, figures). `make paper`, `make pitch` and `make blog` re-derive from committed raw data and render, without measuring. That is the "fastest path" and is what makes "regenerates from a clean clone" (B5) achievable. `make paper-data` runs the T1 measurements for the current machine. `make all` = every measurement target, then every kit.
- Reporting across the two runs → `make perf` performs `perf.runs` (2) back-to-back runs in one session. The agreement check (±`perf.agreement_tolerance`) compares per-run medians. Reported numbers pool the samples of all runs in the latest session.
- Hardware-CRC-disabled zlib → on aarch64, add `-U__ARM_FEATURE_CRC32` to the default CFLAGS. zlib 1.3.2 `crc32.c` enables `ARMCRC32` only when that macro is defined. On x86_64, stock zlib has no hardware-CRC path, so the control build is byte-for-byte the same configuration and `subjects.lock.json` records `control_identical_to_default: true`. Disassembly (`crc32[bhwx]` / `pclmulqdq`) is the deciding evidence in every case.
- Similarity metrics → the primary metric is a tree-sitter token n-gram Jaccard over a cross-language normalized token vocabulary, for every pair including the cross-language positive control. Identifier overlap and comment n-gram overlap are computed for every pair. JPlag 6.3.0 is secondary, for same-language pairs only, after its Rust support is verified. Dolos is not used: one verified tool plus the documented fallback satisfies §3.8.
- Decompression-path scoping → one manifest, `config/decomp_paths.toml`, scopes both similarity (§3.8) and LOC (§3.7), so the two measure the same code. The method is written up in `docs/methods/decomp-paths.md`.
- Similarity positioning → for each metric, position = (score − negative) / (positive − negative). "At or near the negative control" means position ≤ `similarity.near_fraction` (0.25). If the controls are not separated (positive ≤ negative), that metric reports "controls not separated" and cannot support a claim.
- §3.3 "roughly match" → cf's gzip framing overhead is within ±`framing.hypothesis_tolerance` (0.25, relative) of zlib-nohw's on both machines → confirmed. Outside the band on both → refuted. Anything else, or missing data → inconclusive. Actual numbers are always printed.
- Hypothesis verdicts (H1, H2) → Spearman rho with a seeded permutation p-value. Confirmed: rho has the hypothesised sign, |rho| ≥ `content.min_abs_rho` (0.5) and p < `content.alpha` (0.05). Refuted: p < alpha with the opposite sign, or |rho| < `content.null_abs_rho` (0.2). Otherwise inconclusive.
- Effort sources → token usage is extracted from Claude Code transcripts (`effort.transcripts_dir`, default `~/.claude/projects/-media-ericmann-Data-Projects-cleanflate`) into a content-free export committed under `data/raw/effort/any/`. Raw transcripts are never committed. Prices live in `config/pricing.toml` and ship as `null` with `source = "UNSET"`, so cost is reported as a documented gap until a human fills them in. Numbers are never invented.
- Paper figure → a cf/mox/zlib throughput bar chart (Silesia, raw framing, level 6, one-shot, both machines) annotated with `unsafe` counts. It depends only on B1/B2 data. `paper.figure = "trajectory"` switches the kit to the Phase 4 trajectory chart.
- Bomb sweep → a single DEFLATE stream tops out near 1032:1, so the ≥1:1,000,000 point is reached with nested gzip (two layers, each decoded by the subject). The sweep reports per-layer and overall ratios.
- Minimal programs (§3.7) → decode zlib framing (the only framing every subject supports) from stdin to stdout. zsys is excluded from binary size because it is a dynamically linked system library, and the parity note says so.
- Parallel streams → none. Every phase is a short dependency chain, and the shared hotspots (Makefile, `pyproject.toml`, workspace `Cargo.toml`, `config/bench.toml`) are touched by most tasks. The plan is fully serial.
- ⚠️ ASSUMPTION markers → SPEC has none, so there are no tuning tasks. Every numeric default SPEC states (≥30 samples, ±5%, 4 CPU-hours, n-gram 5–10, identifier length ≥6, top-20, buffer sizes, checksum sizes) is a key in `config/bench.toml` and is never a literal in code.
- Open tool questions (JPlag Rust support, cargo-geiger/rust-code-analysis installability) → each is handled inside its task by the tool-gap protocol (CLAUDE.md), with a documented fallback, rather than as a separate spike.

## Conventions
- Commit title `<ID>: <title>`; the body follows CLAUDE.md `## Commit template`.
- Every task leaves `make lint` and `make test` green. Both are `docs/foundry.json` verify commands.
- Config: `config/bench.toml` (tunables), `config/subjects.toml` (pins), `config/rounds.json` (round SHAs), `config/tools.toml` (tool versions), `config/decomp_paths.toml`, `config/pricing.toml`, `config/rfc_identifiers.txt`, `config/similarity_verdicts.toml`.
- Subject ids: `cf`, `zlib`, `zlib-nohw`, `zng`, `zrs`, `mox`, `zsys`; native variants `cf@native`, `zrs@native`, `mox@native`; rounds `cf-r1`, `cf-r2`, `cf-r3`.
- Machine ids: `M-A` (Darwin arm64), `M-B` (Linux x86_64), `any` (machine-independent categories); `CFB_MACHINE` overrides.
- Raw: `data/raw/<category>/<machine>/<UTC yyyymmddTHHMMSSZ>.json` (full profile, committed); quick/smoke runs go to `data/smoke/` (gitignored). Derived: `results/<name>.csv` plus `results/<name>.csv.provenance.json`; figures `results/figures/<name>.svg` plus a 2× `.png`.

Output is JSON with `sort_keys=True, indent=1`. Also `list_raw(category, machine=None, profile="full", kind=None) -> list[Path]` (sorted; `kind` filters on `payload["kind"]`), `load_raw(path) -> dict` (validates `schema`), and `latest_session(category, machine, kind=None) -> list[dict]` (every raw document sharing the newest `session`, sorted by `run_index`).

- `python -m cfbench.env` captures, writes category `env` (payload `{"kind": "env"}` plus the capture) and copies the capture to `environment.json` (gitignored). `make env` runs it.

### P0-04: Pinned C subject builds (zlib, zlib-nohw, zlib-ng)
**Goal:** Download pinned zlib 1.3.2 and zlib-ng 2.3.3 sources and build the static libraries `zlib`, `zlib-nohw` and `zng`, recording compiler, version and flags for each.
**Files touched:** `config/subjects.toml`, `cfbench/download.py`, `cfbench/cbuild.py`, `Makefile`, `tests/test_download.py`, `tests/test_cbuild.py`
**Design constraints:**
- SPEC §2.1 and §2.3. Follow the pinned-download protocol in CLAUDE.md.
- `config/subjects.toml`: `[zlib] version = "1.3.2"`, `url = "https://github.com/madler/zlib/releases/download/v1.3.2/zlib-1.3.2.tar.gz"`, `sha256 = "<computed>"`; `[zng] version = "2.3.3"`, `url = "https://github.com/zlib-ng/zlib-ng/archive/refs/tags/2.3.3.tar.gz"`, `sha256 = "<computed>"`; `[zrs] crate = "libz-rs-sys"`, `core_crate = "zlib-rs"`, `version = "0.6.8"`; `[mox] crate = "miniz_oxide"`, `version = "0.9.1"`.
- `download.fetch(url, sha256, dest_dir) -> Path` caches in `third_party/downloads/` and verifies SHA-256. A mismatch raises. If `sha256` is empty, it raises with the computed value in the message, so the implementer can pin it. `download.extract(tarball, dest)` extracts into `third_party/src/<name>-<version>/`.
- `cbuild` builds into `build/c/<id>/{lib,include}` and writes `build/c/<id>/build-info.json` last: `{id, version, source_sha256, compiler, compiler_version, cflags, configure_args | cmake_options, arch, built_from}`.
  - `zlib`: copy the source to `build/c/zlib/src`, run `./configure --static --prefix=<build/c/zlib>` with zlib's own default CFLAGS (do not set CFLAGS), then `make libz.a install`. Copy `lib/libz.a` to `lib/libcfbz_default.a`.

## Spec issues
1. §2.3 says to record each Rust subject's `unsafe` status "from inspection (§3.4)", but the unsafe inspection is §3.7 (§3.4 is content analysis). Resolution: read it as §3.7. P0-09 records a basic status and P2-04 the full surface.

11. §4 says `make paper` is "T1 only, fastest path", but B5 says it must regenerate from a clean clone, which cannot re-measure two physical machines. Resolution: `make paper` renders from committed raw data, and `make paper-data` measures.
12. The §3.2 full matrix (6 subjects × 207 streams × 3 modes, plus tiny inputs, ≥30 samples, 2 runs) takes several hours per machine. Resolution: full timing runs are human-run on quiet machines, and the implementer validates with the quick profile.

# POST-HOC extended identifier exclusions (added 2026-10-02, after the first full similarity run).
#
# NOT pre-registered. The pre-registered list is config/rfc_identifiers.txt and the T1 claim is
# still decided on it alone. This list feeds a separately reported sensitivity analysis
# (`ident_*_filtered` metrics), applied identically to every pair, controls included.
#
# Why: the first run showed the shared-identifier sets of every Rust pair, controls included, were
# dominated by names the implementer does not choose (attribute and lint names, std method names)
# and by names built from RFC-defined terms. With sets of only ~330-770 names per subject, a few
# such names move a pair's position between the controls by more than the 0.25 "near" band.
#
# Selection rule (by category, not by pair): a name is listed if it is
#   (language) a Rust attribute, attribute argument, lint, derive, std/core trait, macro or
#              method name, or a cfg key; or
#   (rfc)      composed only of terms the RFC 1950/1951/1952 texts define (alphabet, field and
#              structure names) plus a generic suffix (base, extra, bits, table, size, len).
# Zlib API names (inflate, total_in, next_in, avail_in, window_bits, stream_end, ...) stay
# deliberately NOT excluded, as in the pre-registered list: sharing them is a legitimate signal.
# Generic English task words (decompress, decoder, output, status, ...) are also kept.
# Same format as rfc_identifiers.txt: one name per line, normalised (lowercase, no `_`).
